## Plan (not implemented)
Scan (`indexer/scan.rs`), keeping `FileProcessor`/`Indexer` unchanged for S9:
- `IndexMode { Changed (default), Full, Reembed }` (serde snake_case, `ToSchema`); progress callback `&mut dyn FnMut(IndexProgress)` like `model_setup::setup`.
- Per source, load stored path -> (mtime, hash) in one query. `Changed`: same mtime skip; else read+hash; same hash update mtime only; else upsert and run indexer. `Full`: re-read and re-chunk all, embed only new hashes. `Reembed`: delete all vectors then `Full`.
- `IndexReport.files` = notes re-chunked (9 for `--full` on fixture, 0 for unchanged plain run).
- After deletes and before `embed_missing`, prune: `DELETE FROM vectors WHERE text_hash NOT IN (SELECT text_hash FROM chunks)` (safe for renames: one scan sees the whole folder).
- Embed progress: count distinct unembedded texts, report `{embedded, total}` after each batch.

Service (`trove serve`):
- Watcher in its own file (e.g. `http/watcher.rs`) with `notify` (latest stable; 9.0.0-rc.5 is newest listed) in root workspace deps. Watch every source recursively at start; add/remove watches in `POST/DELETE /sources`.
- Filter: ignore `EventKind::Access` (inotify reports the scan's reads, would loop); ignore paths with a component starting with `.` or equal to the store folder (relative to source root); match against both given and canonicalised root (macOS FSEvents reports `/private/var/...`). Paths matching neither root and `need_rescan()` count as relevant.
- Debounce: `config.index_debounce` quiet time after last relevant event, then one `Changed` scan over all sources.
- One run at a time: startup scan, watcher runs and `POST /index` share a tokio mutex; queued/running job holds an `Activity` guard and marks busy. Startup scan marked queued synchronously in `Service::start`, spawned in `run` after the watcher is watching.
- Events: `index_started {mode}`, `index_progress {embedded, total}`, `index_finished {report}`, `index_failed {message}` (also stderr). Broadcast send with no subscribers is not an error.
- `/status`: add `indexing: {busy, embedded}` (`embedded` = chunk texts embedded since service start; S12 uses it for "zero model calls"). Keep `index`/`model` keys and CLI `status` output unchanged (`crates/trove/tests/serve.rs` asserts them exactly).
- `POST /index` takes `{mode?}` with `deny_unknown_fields`, 400 on bad JSON via `Result<Json<_>, JsonRejection>` as in `http/search.rs`.
- CLI `index [--full] [--reembed]` sends mode through `Service::post`; `--reembed` implies `--full`.

Tests (new file e.g. `crates/trove/tests/change_detection.rs`, real model, `vault_copy()`, `index_debounce = "200ms"`):
