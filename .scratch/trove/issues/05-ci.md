## What to build

GitHub Actions on native Windows, macOS arm64 and Linux runners (spec "Build and release"): build llama.cpp per platform (Metal static on macOS, shared with runtime backends elsewhere), cache the model file by its pinned revision, run clippy and tests. Add the cross-backend tolerance check from spec test seam 2.

## Comments

Workflow: `.github/workflows/ci.yml`, one matrix job per OS (`windows-2025`, `macos-15` arm64, `ubuntu-24.04`), runs on every push and pull request. Rust is pinned to 1.97.1 through `rustup` (no `rust-toolchain.toml`). Steps: `Swatinem/rust-cache` for dependencies, the llama.cpp cache, the model cache (download on miss), `cargo clippy --locked --all-targets -- --deny warnings`, `cargo test --locked`. Nothing beyond the runner images is installed: they already have git, CMake and the C/C++ toolchains (MSVC, Xcode clang, GCC 13).

Caches.
- llama.cpp: `build.rs` builds inside each build script's `OUT_DIR`, so the cache is `target/debug/build/trove-llama-*/out`, keyed `llama-cpp-<os>-<rust version>-<hash of Cargo.lock, build.rs, the patch>`. Clippy and test get separate `OUT_DIR`s (cargo hashes clippy's workspace wrapper into the build script's metadata), so a cold run builds llama.cpp twice and the cache holds both (38 MB macOS, 60 MB Windows, 71 MB Linux compressed). On a hit cargo reruns `build.rs`, which reuses the checkout and lets CMake find the build up to date. The Windows key differs from the others because checkout gives `build.rs` CRLF there.
- Model: `~/.cache/huggingface/hub/models--ggml-org--embeddinggemma-2-GGUF`, keyed `model-<os>-<revision>-<file>`. The repo, revision, file and SHA-256 are read from `model_setup.rs` (single source); on a miss the file is fetched with curl from `resolve/<revision>` into the `hf download` snapshot layout and checked with `openssl dgst -sha256` before it gets its final name.

Cross-backend check (spec seam 2): `metal_and_cpu_vectors_for_the_reference_texts_agree` in `crates/trove-core/tests/embedder.rs`, compiled on macOS only. It asserts llama.cpp found a GPU (`embedder::has_gpu`), then embeds the reference texts with the default devices (Metal) and with `Embedder::on_devices(.., Devices::Cpu)` and fails below cosine 0.999. `Devices::Cpu` passes llama.cpp an empty device list, so no GPU is picked. `Embedder::new` is unchanged (it uses `Devices::Default`); `EmbeddingModel::load` takes the `Devices`. Bindings regenerated for `ggml_backend_dev_get` and `ggml_backend_dev_type`. The GitHub macOS arm64 runner has a working Metal device; the macOS build needed no changes.

Runs.
- https://github.com/marioparaschiv/trove-rust/actions/runs/38740358479: first push. macOS and Linux green; Windows failed in the model download (no `shasum` in Git Bash on the runner, fixed by using `openssl`). Linux was cancelled by mistake after it had already passed, so its caches were saved.
- https://github.com/marioparaschiv/trove-rust/actions/runs/38743353005 attempt 1: all three green. macOS and Linux hit both caches; Windows cold.
- Same run, attempt 2 (re-run, no changes): all three green with cache hits for llama.cpp and the model on every OS ("Cache restored from key: llama-cpp-...", "model-...").

Timings. Cold llama.cpp build (each of clippy and test): macOS about 35 s (one CPU backend plus Metal), Windows about 8 min, Linux about 9.5 min (every `ggml-cpu-*` variant on 4 cores). Whole job cold: macOS 2 min, Windows 18 min, Linux 20 min. Warm: macOS 1 min, Linux 1.5 min, Windows 4 min (its dependency cache missed once because the runner's Rust environment hash changed between attempts; it heals on the next save). The embedder tests take about 35 s on each runner.

For release builds (18).
- Windows: ship `llama.dll`, `ggml.dll`, `ggml-base.dll` and every `ggml-cpu-*.dll` beside `trove.exe` (ggml loads backends from the executable's folder); users need the VC++ runtime (`msvcp140`, `vcruntime140`, `vcomp140`), or ship those too.
- Linux: ship `libllama.so`, `libggml.so`, `libggml-base.so` and every `libggml-cpu-*.so` beside `trove`, and link `trove` with an `$ORIGIN` rpath (cargo's `LD_LIBRARY_PATH` covers only `cargo run`/`cargo test`). Built here with GCC 13 on x86_64; arm64 would need GCC 14+ or Clang for the armv9.2 variants.
- macOS: one static binary (Metal library embedded), deployment target 14.0; nothing to ship beside it.
- A release profile gets its own `OUT_DIR`, so cache `target/release/build/trove-llama-*/out` the same way.
